### 2.1 · Scan flow (the user journey)

1. **Camera** — `image_picker` opens the system camera on the iQOO.
2. **OCR** — `google_mlkit_text_recognition` runs the recognizer on the captured image. The image stays on the phone.
3. **Preview** — `main_screen.dart` displays the captured text and detected variables. The user can edit before submitting.
4. **Submit** — `POST /scan` sends the image + extracted text + a Firebase ID token.
5. **Backend picks a template** — `services/ai_detector.py` (or the hardcoded `routers/visualiser.py` rules) maps the text to a topic and a template.
6. **AI services run in parallel** — `ai_visualiser.py`, `ai_notes.py`, `ai_quiz.py` build the three response payloads.
7. **Response** — `{ visualiser: {...}, notes: {...}, quiz: [...], topic, variables }` is returned.
8. **Render** — `VisualiserFactory` chooses a Flutter widget; the user sees the AI Visualiser tab, with Notes and Quiz as adjacent tabs.
9. **Persist** — `history_store.dart` writes the scan to `SharedPreferences`; the coin store awards 10 Quanta coins.

### 2.2 · History

The History tab is the entry point for repeat visits. Each row shows topic, subject, date, and a star. The detail screen is the same Scan Result screen with a placeholder image if the original is gone. `history_detail_screen.dart` has special handling for demo placeholders (paths containing `/demo_scans/`) so they don't render as a broken-image box.

### 2.3 · Dev auth bypass

`firebase_auth_service.dart` returns a constant `_kDevBypassToken = 'test-token'` when no Firebase user is signed in. The backend's `auth_middleware.py` honours the same token when `ALLOW_DEV_AUTH_BYPASS=true`. This is the loop that lets the team run the full app without a real Firebase project during the hackathon.

### 2.4 · On-device AI

The OCR is the only model running on the device today. The visualiser parameter sliders re-render the `CustomPainter` with no network round-trip, so the simulation is responsive even at 30 fps on a Snapdragon NPU. The team's roadmap includes a `tflite_flutter` or `ggml` quantised model for on-device quiz grading and topic classification.

### 3.1 · The visualiser dispatch

`routers/visualiser.py` keeps a list of `topic_keyword → template_id` rules. For the iQOO demo the team wired these manually (the AI detector would normally suggest them):

| Keywords | Template |
|---|---|
| `projectile`, `parabola`, `launch` | `projectile_motion.json` |
| `simple harmonic`, `shm`, `spring` | `shm.json` |
| `atom`, `bohr`, `electron`, `carbon`, `z =`, `proton` | `kinematics.json` (atom variant) |
| `water`, `h2o`, `molecule`, `bond` | `kinematics.json` (molecule variant) |
| `wave`, `string`, `sinusoid` | `kinematics.json` (wave variant) |
| `free fall`, `gravity drop` | `free_fall.json` |
| `equation`, `quadratic`, `roots` | `graphs.json` |
| `circuit`, `resistor`, `ohm` | `circuits.json` |
| `lens`, `mirror`, `refraction` | `optics.json` |

When a new topic doesn't match, the engine falls back to a generic diagram with the extracted text. `services/ai_visualiser.py` is where a Gemini call can rewrite the template for richer, parameter-rich topics.

### 3.2 · Auth

`auth_middleware.py` is a FastAPI dependency that:

1. Reads `Authorization: Bearer <token>` from the request.
2. If `ALLOW_DEV_AUTH_BYPASS=true` and the token is `test-token`, accepts the request and attaches a synthetic `dev-user` to the request state.
3. Otherwise, verifies the token with `firebase-admin` and attaches the real `uid`.

The dev-bypass path is the only way the local phone build can talk to the local backend during the hackathon without a Firebase project.

### 3.3 · Storage

- **Local dev** — images land in `backend/static/uploads/`. The route `/static/uploads/{filename}` serves them.
- **Vercel deploy** — `static/uploads/` is ephemeral; the team uses Vercel Blob or an S3-compatible store. (Hackathon scope: local-only.)

### 3.4 · AI services

All four AI services (`ai_visualiser`, `ai_notes`, `ai_quiz`, `ai_chat`) follow the same shape:

```python
async def generate(payload: ScanPayload) -> OutputModel:
    prompt = build_prompt(payload)
    raw = await call_gemini(prompt, model="gemini-2.5-flash")
    return OutputModel.model_validate_json(safe_json(raw))
```

`ai_detector.py` is the classifier that runs first; it picks a `topic` and a `subject` (physics / chemistry / maths / other) so the visualiser can route to the right template.

## 4 · Data shapes

### 4.1 · Scan (the unit of work)

```jsonc
{
  "id": "uuid",
  "user_id": "firebase-uid-or-dev-user",
  "image_path": "static/uploads/<uuid>.jpg",
  "raw_text": "A ball is launched at 20 m/s at 45° ...",
  "topic": "Projectile Motion — launch angle 45°, v₀ = 20 m/s",
  "subject": "physics",
  "variables": ["v0 = 20 m/s", "θ = 45°", "g = 9.8 m/s²"],
  "visualiser": {
    "template_id": "projectile_motion",
    "params": { "v0": 20, "angle_deg": 45, "g": 9.8 }
  },
  "notes": {
    "concept": "...",
    "formulas": ["R = v₀² sin(2θ) / g", "..."],
    "key_points": ["..."],
    "worked_example": ["..."]
  },
  "quiz": [
    { "q": "...", "options": ["A","B","C","D"], "answer": 2 }
  ],
  "quiz_results": [{ "score": 5, "total": 5, "timestamp": "..." }],
  "is_starred": false,
  "created_at": "2026-09-02T09:00:00Z"
}
```

The phone mirrors this into `SharedPreferences` under the key `quanta_history_v1`, which is the on-device source of truth for the History tab.

### 4.2 · Visualiser template

```jsonc
{
  "template_id": "projectile_motion",
  "title": "Projectile Motion",
  "renderer": "projectile_motion.dart",
  "defaults": { "v0": 20, "angle_deg": 45, "g": 9.8 },
  "ranges":   { "v0": [5, 60], "angle_deg": [10, 80], "g": [1, 25] },
  "axes":     { "x": "Distance (m)", "y": "Height (m)" }
}
```

`VisualiserFactory` looks up the `renderer` and instantiates the matching widget with the supplied `params`.

## 5 · Why this shape

- **Phone-first rendering** — every visualiser is a Flutter widget. No WebView, no remote canvas. Animation runs at the device's refresh rate, with the NPU available for future on-device work.
- **Templated backend** — the visualiser service is a small router over a handful of JSON templates. New topics take minutes, not sprints.
- **Local-first history** — the History tab is built from `SharedPreferences`, so the app is useful even on a flaky network. The backend mirror is a sync, not a source of truth.
- **Hackathon-friendly auth** — the dev bypass means a fresh checkout runs end-to-end with two `pip install` + `flutter run` lines, no Firebase project.

---

## 6 · What's not in this diagram

- **Office Kit bridge** — used during the hackathon to mirror the laptop to the phone, transfer build APKs, and demo the running build. Not part of the runtime product.
- **Vercel serverless** — `vercel.json` is set up for the team's prod push, but the demo runs on a local laptop.
- **Coins ledger** — the on-device coin balance and streak are persisted in `SharedPreferences` with a base64-encoded list under `quanta_coins_ledger_v1`. The backend mirror is best-effort.
